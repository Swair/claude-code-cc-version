# Prosophor 配置说明

本文说明本项目的两类主要配置：

- `config/.prosophor/settings.json`：全局基础配置。
- `config/.prosophor/roles/*.json`：角色配置，每个 role 可以覆盖自己的 LLM、精灵、TTS 等行为。

## 配置职责边界

| 配置文件 | 职责 | 粒度 |
| --- | --- | --- |
| `settings.json` | 全局默认值、provider 池、模型池、本地模型、TTS 基础 provider、权限策略 | 应用级 |
| `roles/<role>.json` | 单个角色的身份、人格、LLM 选择、工具权限、精灵、TTS 声音 | 角色级 |

基本规则：

1. `settings.json` 提供全局可用资源。
2. `roles/*.json` 选择并覆盖这些资源。
3. role 没有配置某项时，使用全局默认配置。
4. role 只应该写它自己关心的差异项，不需要复制完整全局配置。

## settings.json

路径：

```text
config/.prosophor/settings.json
```

### 顶层结构

```json
{
  "default_role": ["architect", "ayaka", "sayu", "keqing"],
  "log_level": "info",
  "enable_summary": false,
  "sprite_assets_dir": "~/.prosophor/assets",
  "providers": {},
  "local_models": [],
  "tts": {},
  "security": {}
}
```

### `default_role`

默认启动的角色列表。

SDL 桌面精灵模式下，列表中每个 role 通常会创建一个 sprite：

```json
"default_role": ["architect", "ayaka", "sayu", "keqing"]
```

TUI 模式一般只使用第一个 role。

### `log_level`

日志级别：

```json
"log_level": "info"
```

常见值：

- `debug`
- `info`
- `warn`
- `error`

### `enable_summary`

全局对话摘要开关：

```json
"enable_summary": false
```

role 内也可以通过 `llm.enable_summary` 覆盖。

### `sprite_assets_dir`

用户精灵资源目录：

```json
"sprite_assets_dir": "~/.prosophor/assets"
```

当 role 使用 `sprite_id` 或 sprite 资源时，会优先从这里查找对应资源。

## providers

`providers` 是 LLM provider 池。它定义应用可用的模型供应商、API 地址和模型列表。

结构示例：

```json
"providers": {
  "openai": [
    {
      "api_key": "sk-...",
      "base_url": "http://localhost:8080/v1/chat/completions",
      "timeout": 120,
      "models": [
        {
          "model": "google_gemma-4-E4B-it-Q4_K_M",
          "temperature": 0.7,
          "max_tokens": 8192,
          "context_window": 32768,
          "thinking": true
        }
      ]
    }
  ]
}
```

### provider 类型

当前常见 provider key：

| Key | 用途 |
| --- | --- |
| `anthropic` | Anthropic Messages API 兼容接口 |
| `openai` | OpenAI Chat Completions 兼容接口 |
| `ollama` | Ollama 本地模型接口 |

### provider 字段

| 字段 | 含义 |
| --- | --- |
| `api_key` | API key。即使本地模型为空也允许存在 |
| `base_url` | API 地址 |
| `timeout` | 请求超时时间，单位秒 |
| `models` | 当前 provider 下可用模型列表 |

### models 字段

| 字段 | 含义 |
| --- | --- |
| `model` | 模型名称 |
| `temperature` | 采样温度 |
| `max_tokens` | 最大输出 token 数 |
| `context_window` | 上下文窗口大小 |
| `thinking` | 是否启用思考模式配置 |

role 通过 `llm.protocal` 和 `llm.model` 选择这里的 provider/model。

## local_models

`local_models` 定义本地 llama-server 模型。

```json
"local_models": [
  {
    "model_path": "../llama_cpp_model/model.gguf",
    "model_path_for_win": "/e/ai_ws/llama_cpp_model/model.gguf",
    "port": 8080,
    "n_gpu_layers": 0,
    "n_threads": 0,
    "auto_start": false,
    "start_timeout_ms": 150000
  }
]
```

| 字段 | 含义 |
| --- | --- |
| `model_path` | 非 Windows 环境下的模型路径 |
| `model_path_for_win` | Windows / MSYS2 环境下的模型路径 |
| `port` | llama-server 监听端口 |
| `n_gpu_layers` | GPU offload 层数 |
| `n_threads` | CPU 线程数，`0` 表示默认 |
| `auto_start` | 是否自动启动 llama-server |
| `start_timeout_ms` | 等待模型服务就绪的超时时间 |

## tts

`settings.json` 中的 `tts` 是 TTS 基础配置池，不绑定具体角色。

```json
"tts": {
  "enabled": true,
  "provider": [
    {
      "backend": "gpt-sovits",
      "gs_url": "http://127.0.0.1:9880",
      "gs_install_path": "E:/ai_ws/GPT-SoVITS",
      "gs_auto_start": false,
      "gs_port": 9880,
      "gs_ref_audio_path": "",
      "gs_ref_audio_text": "",
      "gs_ref_audio_lang": "zh",
      "gs_text_lang": "zh"
    },
    {
      "backend": "edge-tts",
      "voice": "zh-CN-XiaoyiNeural",
      "auto_start": false
    }
  ]
}
```

### tts 顶层字段

| 字段 | 含义 |
| --- | --- |
| `enabled` | 全局 TTS 开关 |
| `provider` | 可用 TTS provider 列表 |

### edge-tts provider

```json
{
  "backend": "edge-tts",
  "voice": "zh-CN-XiaoyiNeural",
  "auto_start": false
}
```

| 字段 | 含义 |
| --- | --- |
| `backend` | 固定为 `edge-tts` |
| `voice` | 默认 voice，role 未覆盖时使用 |
| `auto_start` | 保留字段。edge-tts 是命令行工具，通常不需要启动服务 |

### GPT-SoVITS provider

```json
{
  "backend": "gpt-sovits",
  "gs_url": "http://127.0.0.1:9880",
  "gs_install_path": "E:/ai_ws/GPT-SoVITS",
  "gs_auto_start": false,
  "gs_port": 9880,
  "gs_ref_audio_path": "",
  "gs_ref_audio_text": "",
  "gs_ref_audio_lang": "zh",
  "gs_text_lang": "zh"
}
```

| 字段 | 含义 |
| --- | --- |
| `backend` | 固定为 `gpt-sovits` |
| `gs_url` | GPT-SoVITS API 地址 |
| `gs_install_path` | GPT-SoVITS 安装路径 |
| `gs_auto_start` | 是否自动启动 GPT-SoVITS API |
| `gs_port` | API 端口 |
| `gs_ref_audio_path` | 参考音频路径 |
| `gs_ref_audio_text` | 参考音频对应文本 |
| `gs_ref_audio_lang` | 参考音频语言 |
| `gs_text_lang` | 输入文本语言 |

## security

```json
"security": {
  "allow_local_execute": true,
  "permission_level": "auto"
}
```

| 字段 | 含义 |
| --- | --- |
| `allow_local_execute` | 是否允许本地执行工具命令 |
| `permission_level` | 权限级别，例如 `auto` |

## roles/*.json

路径：

```text
config/.prosophor/roles/<role_id>.json
```

role 文件定义一个角色的身份、人格、模型、工具权限、精灵和 TTS 覆盖项。

### 推荐结构

```json
{
  "id": "architect",
  "display_name": "架构师",
  "description": "资深系统架构设计专家",
  "spritesheet_path": "skirk-2.webp",
  "personality_prompt": "你善于从宏观角度分析，关注系统设计的可扩展性、可维护性和权衡取舍。",

  "llm": {
    "protocal": "openai",
    "model": "google_gemma-4-E4B-it-Q4_K_M",
    "skills_white_list": ["system-design", "architecture-patterns", "tech-radar"],
    "tools_white_list": ["*"],
    "max_iterations": 15,
    "auto_confirm_tools": true
  },

  "tts": {
    "provider": "edge-tts",
    "voice": "zh-CN-XiaoyiNeural"
  }
}
```

## role 顶层字段

| 字段 | 含义 |
| --- | --- |
| `id` | role 唯一标识，通常与文件名一致 |
| `display_name` | UI 显示名称 |
| `description` | 角色描述 |
| `spritesheet_path` | 精灵贴图文件名 |
| `sprite_id` | 指向 petdex sprite 的 id |
| `sprite_assets_dir` | 指定精灵资源目录 |
| `personality_prompt` | 角色人格提示词 |
| `llm` | LLM 配置覆盖 |
| `tts` | TTS 配置覆盖 |

### sprite 字段选择

常用方式：

```json
"spritesheet_path": "keqing.webp"
```

也可以使用：

```json
"sprite_id": "keqing"
```

或：

```json
"sprite_assets_dir": "E:/path/to/sprite/assets"
```

优先级通常是显式资源配置优先，其次再从默认资源目录或 petdex 查找。

## role.llm

```json
"llm": {
  "protocal": "openai",
  "model": "google_gemma-4-E4B-it-Q4_K_M",
  "skills_white_list": ["*"],
  "tools_white_list": ["*"],
  "max_iterations": 30,
  "auto_confirm_tools": true,
  "enable_streaming": true,
  "enable_summary": true,
  "memory_dir": "~/.prosophor/memories/keqing"
}
```

| 字段 | 含义 |
| --- | --- |
| `protocal` | provider 名称。当前保留原拼写 `protocal` |
| `model` | 模型名，必须能在 `settings.json.providers` 中找到 |
| `skills_white_list` | 允许加载的技能列表，`["*"]` 表示全部 |
| `tools_white_list` | 允许使用的工具列表，`["*"]` 表示全部 |
| `max_iterations` | 单轮最大工具调用迭代次数 |
| `auto_confirm_tools` | 是否自动确认工具调用 |
| `enable_streaming` | 是否启用流式输出 |
| `enable_summary` | 是否启用摘要 |
| `memory_dir` | 角色专属记忆目录 |

### protocal 与 model 匹配

role 中：

```json
"llm": {
  "protocal": "openai",
  "model": "google_gemma-4-E4B-it-Q4_K_M"
}
```

表示：

1. 到 `settings.json.providers.openai` 中查找。
2. 找到包含 `model = google_gemma-4-E4B-it-Q4_K_M` 的 provider 配置。
3. 使用该 provider 的 `base_url` / `api_key` / `timeout` 和 model 参数。

也支持在 `model` 中写组合格式：

```json
"model": "openai:google_gemma-4-E4B-it-Q4_K_M"
```

当 `protocal` 为空时，会尝试从组合格式中解析 provider。

## role.tts

role 级 TTS 配置用于覆盖全局 TTS 默认值。

```json
"tts": {
  "provider": "edge-tts",
  "voice": "zh-CN-XiaoyiNeural"
}
```

| 字段 | 含义 |
| --- | --- |
| `provider` | TTS provider 名称，如 `edge-tts` 或 `gpt-sovits` |
| `backend` | 兼容字段，等价于 `provider` |
| `voice` | voice 名称。edge-tts 使用 Microsoft voice 名称 |
| `auto_start` | role 级自动启动覆盖，当前主要保留给需要服务进程的 provider |

### role.tts 继承规则

如果 role 没有配置 `tts`：

```json
{
  "id": "keqing",
  "display_name": "Keqing",
  "llm": {}
}
```

则使用 `settings.json` 中默认 TTS provider。

如果 role 配置了：

```json
"tts": {
  "provider": "edge-tts",
  "voice": "zh-CN-XiaoyiNeural"
}
```

则当前 role 使用自己的 `provider + voice`。

## 配置解析优先级

### LLM

```text
role.llm.protocal + role.llm.model
        ↓
settings.providers[protocal]
        ↓
匹配 model 名称
        ↓
使用对应 provider/model 配置
```

### TTS

```text
settings.tts.enabled
        ↓
settings.tts.provider[] 提供基础 provider 池
        ↓
role.tts.provider / role.tts.voice 可覆盖当前角色 TTS
        ↓
回复完成后触发 TTS
```

### Sprite

```text
role.spritesheet_path / role.sprite_id / role.sprite_assets_dir
        ↓
settings.sprite_assets_dir
        ↓
默认 petdex 资源
```

## 示例：全局 edge-tts + role 覆盖 voice

`settings.json`：

```json
"tts": {
  "enabled": true,
  "provider": [
    {
      "backend": "edge-tts",
      "voice": "zh-CN-XiaoyiNeural",
      "auto_start": false
    }
  ]
}
```

`roles/architect.json`：

```json
"tts": {
  "provider": "edge-tts",
  "voice": "zh-CN-XiaoyiNeural"
}
```

`roles/keqing.json` 不写 `tts` 时，会使用全局默认 `edge-tts` 配置。

## 注意事项

- 不要把真实 API key 提交到公开仓库。
- role 文件只写差异配置，避免复制完整 `settings.json`。
- `protocal` 当前按项目已有字段拼写保留，不要改成 `protocol`，除非代码同步兼容。
- edge-tts 的 voice 列表可用 `edge-tts --list-voices` 查看。
- TTS 缓存建议按 `role + provider + voice + text` 生成 key，避免不同角色或不同声音串缓存。
